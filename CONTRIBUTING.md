# Руководство по участию в проекте

Спасибо за интерес к проекту TBL Editor! Мы приветствуем вклад от сообщества.

## 🎯 Как внести вклад

### Сообщение об ошибках

Если вы нашли ошибку, пожалуйста, создайте [Issue](https://github.com/yourusername/tbl-editor/issues) с следующей информацией:

1. **Чёткое описание** проблемы
2. **Шаги для воспроизведения**:
   - Что вы делали
   - Что ожидали увидеть
   - Что произошло на самом деле
3. **Окружение**:
   - Версия браузера
   - Операционная система
   - Версия Node.js (если применимо)
4. **Скриншоты** (если возможно)
5. **Логи ошибок** (если есть)

### Предложение новых функций

Мы открыты для новых идей! Перед созданием Issue:

1. Проверьте, что такая функция уже не предложена
2. Опишите проблему, которую решает функция
3. Предложите возможное решение
4. Обсудите альтернативы

### Внесение изменений в код

#### 1. Форкните репозиторий

```bash
git clone https://github.com/yourusername/tbl-editor.git
cd tbl-editor
```

#### 2. Создайте ветку

```bash
git checkout -b feature/название-функции
# или
git checkout -b fix/описание-исправления
```

#### 3. Внесите изменения

- Следуйте существующему стилю кода
- Добавляйте комментарии к сложным частям кода
- Обновляйте документацию при необходимости
- Добавляйте тесты для нового функционала

#### 4. Проверьте код

```bash
# Проверка типов
npm run type-check

# Проверка стиля кода
npm run lint

# Запуск тестов
npm run test

# Сборка проекта
npm run build
```

#### 5. Закоммитьте изменения

Используйте [Conventional Commits](https://www.conventionalcommits.org/):

```bash
git commit -m "feat: добавлена функция экспорта в CSV"
git commit -m "fix: исправлена ошибка шифрования"
git commit -m "docs: обновлён README"
git commit -m "style: форматирование кода"
git commit -m "refactor: рефакторинг модуля импорта"
git commit -m "test: добавлены тесты для TBL парсера"
git commit -m "chore: обновление зависимостей"
```

#### 6. Отправьте изменения

```bash
git push origin feature/название-функции
```

#### 7. Создайте Pull Request

- Опишите изменения подробно
- Укажите связанные Issues
- Добавьте скриншоты (если изменения визуальные)
- Дождитесь ревью

## 📝 Стиль кода

### TypeScript

- Используйте строгую типизацию
- Избегайте `any` типов
- Добавляйте типы для всех функций и компонентов
- Используйте интерфейсы для объектов

```typescript
// ✅ Хорошо
interface User {
  id: number;
  name: string;
  email: string;
}

function getUser(id: number): User {
  // ...
}

// ❌ Плохо
function getUser(id: any): any {
  // ...
}
```

### React

- Используйте функциональные компоненты с хуками
- Разбивайте большие компоненты на меньшие
- Используйте `useCallback` и `useMemo` для оптимизации
- Добавляйте PropTypes или TypeScript типы

```typescript
// ✅ Хорошо
const Button: React.FC<ButtonProps> = ({ onClick, children }) => {
  const handleClick = useCallback(() => {
    onClick();
  }, [onClick]);

  return <button onClick={handleClick}>{children}</button>;
};

// ❌ Плохо
function Button(props) {
  return <button onClick={props.onClick}>{props.children}</button>;
}
```

### CSS

- Используйте CSS переменные для темизации
- Следуйте BEM методологии (если применимо)
- Избегайте inline стилей (кроме динамических)
- Используйте Tailwind CSS классы

```css
/* ✅ Хорошо */
.button {
  background-color: var(--accent);
  color: var(--text-primary);
}

/* ❌ Плохо */
.button {
  background-color: #8b5cf6;
  color: #f5f5f5;
}
```

### Именование

- **Компоненты**: PascalCase (`ThemeToggle.tsx`)
- **Функции**: camelCase (`handleClick`)
- **Переменные**: camelCase (`userName`)
- **Константы**: UPPER_SNAKE_CASE (`MAX_COUNT`)
- **Типы/Интерфейсы**: PascalCase (`UserProfile`)

## 🧪 Тестирование

Перед отправкой PR убедитесь, что:

- Все существующие тесты проходят
- Новый функционал покрыт тестами
- Код проходит линтинг
- Проект успешно собирается

## 📚 Документация

- Обновляйте README.md при добавлении новых функций
- Добавляйте комментарии к сложным функциям
- Обновляйте CHANGELOG.md
- Добавляйте примеры использования

## 🔍 Процесс ревью

1. Все PR проходят ревью минимум одним мейнтейнером
2. Адресуйте все комментарии ревьюера
3. Убедитесь, что CI/CD проходит успешно
4. После одобрения PR будет смержён
